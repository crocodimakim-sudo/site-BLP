## Критические риски (CRITICAL)

### R-001: VK Pixel и Яндекс.Карты грузятся без consent gate

- **Файл/локация:**
  - `blocks/template.php:131-134` — VK Pixel
  - `js/pages/contacts.js:37-55` (страница `/contacts`) + загружается через `$extra_js` в `pages_php/contacts.php:10` — Яндекс.Карты `api-maps.yandex.ru`
- **Цитата (`blocks/template.php:131-134`):**
  ```php
  <?php if ($vk_pixel_id): ?>
  <!-- VK Pixel -->
  <script>!function(){var t=document.createElement("script"); ... VK.Retargeting.Init(...) ... }();</script>
  <?php endif; ?>
  ```
- **Issue:** Метрика обёрнута consent gate (`template.php:108-128` — действительно проверено: `getConsent()` + `blp:cookie-consent-accepted` event). Однако VK Pixel рендерится сразу — он cookie-tracker для ретаргетинга и идентифицирует пользователя на стороне VK (ООО «ВК», получатель ПД). Аналогично карты: `loadYandexMaps()` отправляет запрос на `api-maps.yandex.ru` сразу при загрузке страницы `/contacts` (виден IP, User-Agent в логах Яндекса), без проверки cookie consent.
- **Rule:**
  - 152-ФЗ ст. 9 ч. 4 п. 1, 6 — обработка ПД, включая передачу третьим лицам, требует конкретного согласия;
  - В `pages_php/cookies.php:92`: «**Загружаются только после Вашего согласия.** На Сайте действует cookie-баннер: до нажатия "Принять всё" аналитические cookies не устанавливаются и аналитические скрипты не загружаются.» — публичное обещание Оператора, нарушение которого = недостоверная информация (ст. 14.7 КоАП + риск иска по ЗоЗПП).
- **Application:** VK Retargeting Pixel = «маркетинговый трекер» (по разъяснениям РКН 2023+ — относится к категории cookies, требующих opt-in, а не opt-out). Карты Яндекс — менее очевидно, но IP передаётся в инфраструктуру Яндекса. На лендинге `02.site-fcb-6mm/index.html` Яндекс.Метрики вообще нет (баннер декларирует её, но кода нет — обратная проблема: декларация без действия).
- **Conclusion:** Нарушение ст. 9 ч. 4 152-ФЗ + противоречие собственной cookie-политике. Штраф по ст. 13.11 ч. 1 КоАП РФ — 60–100 тыс. ₽ для ЮЛ. При жалобе пользователя — приоритетная обработка РКН.
- **Severity:** **CRITICAL**
- **Recommendation:** В `blocks/template.php:131-134` обернуть VK Pixel тем же паттерном, что и Метрика (`blocks/template.php:108-128`):
  ```php
  <?php if ($vk_pixel_id): ?>
  <script>(function(){
    function getConsent(){try{return JSON.parse(localStorage.getItem('blp_cookie_consent'));}catch(e){return null;}}
    function loadVK(){ /* существующий код VK Retargeting */ }
    var c = getConsent();
    if (c && c.accepted === true) loadVK();
    else window.addEventListener('blp:cookie-consent-accepted', loadVK, {once:true});
  })();</script>
  <?php endif; ?>
  ```
  В `js/pages/contacts.js:37-55` — отложить `loadYandexMaps()` до consent или, как минимум, обновить `pages_php/cookies.php` и `pages_php/policy.php` (раздел 7.3) с прямым указанием передачи в Яндекс.Карты.

- **Severity:** **CRITICAL** (легко устраняется — подача уведомления через `pd.rkn.gov.ru` бесплатна и занимает 1–3 дня)
- **Recommendation:**

### R-004: Email-отбивка пользователю без отдельного согласия

- **Файл/локация:** `blocks/send-form.php:191-201`
- **Цитата:**
  ```php
  if ($mailSent && !empty($email)) {
      $userSubject = 'Ваша заявка принята — BLP Board';
      ...
      @mail($email, $userSubject, $userBody, $userHeaders);
  }
  ```
- **Issue:** Сервер автоматически отправляет email на адрес пользователя. Отдельного согласия на email-уведомления нет. Чекбокс `consent` (ст. 9) согласия покрывает «обработку для ответа на заявку» — формально допустимо. Но домен `noreply@building-port.ru` без SPF/DKIM (не проверено) + текст «BLP Board» в подписи может быть классифицирован как маркетинг-рассылка, особенно если пользователь не отметил `marketing`.
- **Rule:** ст. 18 38-ФЗ «О рекламе» — реклама по сетям связи только с предварительного согласия; ст. 9 152-ФЗ.
- **Application:** Текст письма — «Ваша заявка успешно принята. Наш менеджер свяжется...» — это сервисное уведомление, не реклама. Грань тонкая, но допустима. Риск — формальный.
- **Conclusion:** Низкая вероятность претензии РКН, но при жалобе спам-фильтру VK/Mail.ru — возможна блокировка домена.
- **Severity:** **HIGH** (тег маркетинга на домене + отсутствие технических подписей)
- **Recommendation:**
  1. В `pages_php/policy.php` явно перечислить «отправку сервисного email-подтверждения заявки» как цель обработки.
  2. Настроить SPF/DKIM/DMARC для `building-port.ru` (ручная задача DNS).
  3. В `pages_php/consent.php` раздел 3 добавить пункт «Отправка сервисного email-подтверждения о приёме заявки на указанный email».

- **Issue:** Дисклеймер показан **один раз** перед списком серий. На длинной странице (4 серии × прайсы) пользователь, прокручивая вниз, видит только цены без дисклеймера. По разъяснениям ВАС/ВС РФ — «информационный характер цен» должен быть **читаемым в зоне видимости каждой цены**.
- **Rule:** ст. 437, 494 ГК; постановление Пленума ВАС № 16 от 14.03.2014.
- **Application:** Дисклеймер также есть в footer (`blocks/footer.php:46-49`) — это смягчает риск, но не закрывает полностью.
- **Severity:** **MEDIUM**
- **Recommendation:** Добавить мелкий текст «Не оферта · ст. 437 ГК РФ» рядом с каждым `.product-price__value` (либо tooltip при hover).

### R-011: Информация о товаре по ЗоЗПП — частично

- **Файл/локация:** `pages_php/catalog.php` (характеристики), `pages_php/sertificate.php`, `pages_php/contacts.php`
- **Issue:** B2B-обороты не обязывают давать всю информацию по ЗоЗПП, но если хоть один заказ от физ. лица — применяется ст. 8, 10 ЗоЗПП (продавец, страна-производитель, дата, гарантия, состав). На страницах каталога указаны: материал (фиброцемент), размеры, цена, серия. **Не указаны:** страна-производитель, гарантийный срок, нормативный документ (ТУ/ГОСТ).
- **Rule:** Закон РФ № 2300-1 «О защите прав потребителей» ст. 8, 10.
- **Application:** Если 100% покупателей — юр. лица (что вероятно для оптовых поставок), риск минимален. Если допускаются продажи физ. лицам — нужно усилить.
- **Severity:** **MEDIUM**
- **Recommendation:** На странице каталога каждой серии добавить блок «Производитель: …; Страна: РФ; Гарантия: 25 лет; Сертификат: ГОСТ …». Часть информации уже на `/sertificate` — вынести/продублировать.

### R-012: Отсутствует возрастная маркировка на блоге `/blog`

- **Файл/локация:** `pages_php/blog.php`, `pages_php/blog-post.php`
- **Issue:** Если блог публикует материалы общего характера (отделочные материалы) — маркировка не нужна. Но если хоть одна статья содержит описание процессов с риском (резка, монтаж на высоте) — формально ст. 11 ч. 1 п. 4 436-ФЗ требует маркировки 12+ или 16+. Контента в `database/blog.db` я не видел, но рекомендую проверить.
- **Rule:** 436-ФЗ «О защите детей от информации, причиняющей вред их здоровью и развитию».
- **Application:** Низкий риск. Для b2b-контента маркировка не требуется.
- **Severity:** **MEDIUM (превентивно)**
- **Recommendation:** В шаблоне `blog-post.php` добавить опциональную метку `<meta property="og:age_rating" content="0+">` (или 12+/16+ при необходимости).

### R-013: VK Pixel — отсутствие регистрации цели «ретаргетинг» в политике

- **Файл/локация:** `pages_php/policy.php` раздел 4 «Цели обработки», `pages_php/cookies.php` раздел 3.2 (только Яндекс.Метрика)
- **Issue:** Если VK Pixel включён (т. е. `vk_pixel_id` непустой в `database/site_config.json`), это передача данных в ООО «ВК», цель — ретаргетинг рекламы. Это **не упомянуто** ни в политике, ни в чекбоксе согласия, ни в cookie-policy.
- **Rule:** ст. 9 ч. 4 п. 6 152-ФЗ; ст. 18 38-ФЗ.
- **Application:** При активном пикселе — нарушение. При неактивном — нет (но код всё равно рендерится при `$vk_pixel_id`).
- **Severity:** **MEDIUM** (зависит от наличия `vk_pixel_id` на проде)
- **Recommendation:**
  1. Дополнить `pages_php/cookies.php` 3.2 разделом «VK Retargeting» с описанием цели, оператора, периодов хранения, политики ВК.
  2. В чекбоксе согласия добавить «передача обезличенных данных в ООО «ВК» (Россия)».
  3. Гейтить пиксель за consent (см. R-001).

- **Severity:** **LOW** (если есть устная договорённость) / **HIGH** (если нет)

### R-015: Footer link на flaticon — лицензия требует атрибуции

- **Файл/локация:** `blocks/benefits.php:8` — `https://cdn-icons-png.flaticon.com/512/3429/3429851.png`
- **Issue:** Бесплатные иконки flaticon требуют атрибуции в виде ссылки на сайт автора. Атрибуции на сайте нет.
- **Rule:** ст. 1265, 1300 ГК РФ; лицензия Flaticon Free.
- **Severity:** **LOW**
- **Recommendation:** Либо купить premium-лицензию (раз в год), либо добавить атрибуцию в footer: «Иконки: Flaticon», либо хостить SVG локально (своя графика).

### R-016: CSP в Report-Only режиме включает `googletagmanager.com`, `google-analytics.com`

- **Файл/локация:** `.htaccess:53`
- **Issue:** CSP содержит разрешения на Google-домены, хотя GA отключён. Это не нарушение, но создаёт «открытый канал» на случай несанкционированного включения GA.
- **Severity:** **LOW**
- **Recommendation:** Удалить `googletagmanager.com`, `google-analytics.com` из CSP (`script-src` и `connect-src`). После полного отключения GA на бэкенде эти разрешения не нужны.

### R-017: `pages_php/admin/index.php` — пароль `blp2026admin` (упомянут в CLAUDE.md)

- **Файл/локация:** Не код, а CLAUDE.md публикует пароль в plaintext в репозитории.
- **Issue:** Не юридический риск напрямую, но при утечке репозитория = доступ к панели с лидами (имена/телефоны/email). По ст. 19 152-ФЗ Оператор обязан принимать меры по защите ПД.
- **Severity:** **LOW** (репо приватный? — нужно проверить) / **HIGH** (если публичный)
- **Recommendation:** Перенести пароль в переменную окружения / .htpasswd, удалить из CLAUDE.md, заменить пароль немедленно.
